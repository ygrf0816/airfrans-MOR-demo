## 先看清这几条已核实的事实，不要自己再推翻

1. **流场与翼型轮廓的位置是对的。** 我用 Python 按同样的映射把案例 1 的压力场渲染出来，
   与论文的 `fig9_1_case1.png` 逐处对得上，黑色翼型线正好压在吸力区上；
   把 y 翻转之后吸力区跑到翼型下方，明显是错的。所以现在的映射不要改。
   用户觉得"错位"，真正原因是整域视角把翼型压成了一条很小的细缝，
   加上配色范围取全掩膜的最小最大值，近翼型的结构被压成一片青，
   看起来就像图对不上。改的办法是裁窗口加百分位配色，不是改映射。
2. **气动代理与升力的口径已经移植并验证过**，在 `src/lib/proxies.ts`，不要自己另写公式。
   八个已知案例反验：马赫代理差 5.0e-5，分离代理差 1.6e-8，升力差 4.6e-5。
3. **浏览器读原始 AirfRANS 翼型文件的能力我已经写好并验证**，在 `src/lib/vtp.ts`，
   与 Python 侧 `airfrans_to_web.py` 的差是 5e-7。这一条你只需要接界面，不要重写解析。
4. **在线接口 404 的原因已查到。** 现在的代码把请求直接发到用户填的接口地址上。
   实测 `https://api.agnes-ai.cn/v1` 直接 POST 返回 404，
   而 `https://api.agnes-ai.cn/v1/chat/completions` 返回 401（缺鉴权），说明后者才是正确路径。

**数据集来源**。AirfRANS，公开数据集，一千条二维 NACA 翼型的 RANS 解。

雷诺数 200 万到 600 万。附上官方仓库与论文链接的文字说明（不要外链图片）。

**研究思路与主要结论**。思路写三条线，降维、预测、反向设计。
结论列五条，用真实数字：
八度升力最高 1.3512（三种子 1.3470 到 1.3512 一致收敛，相差千分之三以内）；
数据库同口径最优 1.057，官方口径 1.146；
511 条真实样本排序相关 0.983，官方留出集 89 条 0.9936；
11 个反演目标的压力拟合误差全部低于模型地板；

## 四、流场云图的观感

不改映射，改这三处。

1. **改成裁窗口显示**。只画翼型附近，别画整域。
   窗口至少覆盖弦向负 0.5 到 1.8、法向负 0.9 到 0.9，
   再按画布长宽比等比放宽一边。整域是 x 负 2.16 到 4.23、y 负 1.65 到 1.65。
   裁完之后翼型与尾迹会占满画面，就不存在"对不上"的错觉了。
2. **配色范围改成窗口内的百分位**，别再用全掩膜的最小最大值。
   现在的范围是负 3762 到 1545，把近翼型结构压成了一片青。
   改成取窗口内有效值的 2% 与 98% 分位。
3. **修色标**。现在上下两个标签画在色标左边缘上，被色标盖住了。
   把色标单独放一列，标签画在色标**右侧**，左对齐，并且给右边留够宽度；
   上下标签分别对齐色标的顶端与底端，不要压住色标本体。
4. 翼型白线加粗到 1.8 像素，颜色再亮一点，让人一眼看到它压在哪儿。

## 五、降维演示页的上传区改成自动识别

- 提示文字改成 **"支持原始 airRANS 格式数据"**（用户指定的原文，照写）。
- 支持三类输入：
  1. 原始 AirfRANS 翼型文件，扩展名 `.vtp`，文件名形如 `airFoil2D_SST_风速_攻角_...._aerofoil.vtp`。
     直接用 `src/lib/vtp.ts` 的 `parseAerofoilVtp(fileName, arrayBuffer)`，
     它返回 `{name, uInf, aoa, nPoints, cp256, outline}`，拿 `cp256` 当上传的曲线。
     文件解析失败时给中文错误提示，说明需要哪一种文件。
  2. 本作品导出的 JSON（`airfrans_to_web.py` 的产物）。
  3. 列名为 `name,uInf,aoa,s,cp` 的 CSV。
- 自动按扩展名与内容识别，不要让用户选格式。识别不出来时列出支持的三种格式。
- 也支持整目录拖入（`webkitdirectory`），目录里有多个 `_aerofoil.vtp` 时取第一个并说明取了哪个。
- 解析成功后照旧走同一套模态投影，显示坐标与重构误差。
- 界面上说明一句：不需要预先跑 Python 脚本，原始数据可以直接拖进来。
