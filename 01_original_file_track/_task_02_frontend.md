# 任务：演示网页的前端设计与交互实现（视觉和观感是重点）

## 你的角色

你是这个演示作品的前端负责人。已经有人搭好了骨架，你的工作是把四个页面
做成一个拿得出手的作品。目标观感是科技感强、直观、看一眼就明白在讲什么。
评委看这个页面大概只会花三到五分钟，你要在这几分钟里把三件事说清楚。
第一，改一个形状参数，压力分布和流场马上跟着变。第二，一千条真实数据
能用十几个数字概括。第三，说一句话就能得到一版设计。

## 第一件事 几何生成器移植（必须先做，做完先自检）

新建 `app/src/lib/naca.ts`，把 `naca_generator.py` 的算法完整移植过来。要点：

- 厚度分布 `thickness_dist`，`CTE=True` 时四次项系数是 -0.1036。
- 弯度线 `camber_line` 两个分支。参数长度 2 时是四位族，用
  `m = M/100`、`p = P/10`。参数长度 3 时是五位族，用 `c_l = 0.15L`、`x_f = P/20`，
  中间那个 `m` 要用牛顿迭代解出来，迭代容差 1e-15，和 Python 一样。
  `Q=1` 是反弯分支，公式照抄。
- 采样用余弦站位 `beta = pi * linspace(1, 0, N+1)`，`x = (1-cos(beta))/2`。
  注意 `x` 是从 1 递减到 0，也就是说点序是后缘到前缘。
- 拼接顺序是上表面全部点，再接去掉末点的下表面倒序，最后把首尾两点都强制成
  `(1, 0)` 闭合后缘。`nbSamples` 默认 400。
- 再写一个 `geomVector128(params)`，把轮廓按 64 个余弦站位分箱，
  每箱取 `y/c` 的最大值当上表面、最小值当下表面，先上后下，共 128 个数。
  站位容差是 `(c/64)*0.5`。
- 再写一个 `fiveScalar(params, uInf, aoa)`，四位族是
  `[uInf, aoa, M/100, T/100, 0]`，五位族是 `[uInf, aoa, 0.15L, T/100, Q]`。

写完立刻用 `geom_fixture.json` 自检。12 组参数逐组比 128 个数，
最大绝对差必须小于 1e-9。把自检结果写成一个能重复运行的脚本或测试，
放在 `app/src/lib/__selftest__.ts` 或 `app/scripts/` 下都行，只要你能跑给我看。

## 第二件事 假数据层，让页面先跑起来

新建 `app/src/data/mock.ts`，按 `01_DATA_CONTRACT.md` 的形状**确定性地**

- 压力曲线和流场要长得像真东西。可以用几条高斯凹坑拼出前缘吸力峰，
  流场可以用几个解析函数（绕圆柱势流加尾迹衰减）拼出来。不要造出一片噪声。

改 `app/src/data/load.ts`，让它先试着 `fetch` 真实文件，拿不到就退回落假数据。
页面上要有一个明显的角标说明当前是示例数据还是真实数据，切换时不要刷新页面。

## 第三件事 视觉系统（这一部分是你的主要评分点）

新建 `app/src/theme/tokens.css`，把下面这些东西定义成 CSS 变量，全站统一。

- 配色走深色科技风。背景接近纯黑但要带一点蓝，面板比背景亮一档，
  主色用一个高饱和的青色或电光蓝，辅助色用一个暖色做对比，
  警告色和通过色各一个。所有图表、三维场景、按钮、徽标都从这里取色，
  不许在组件里写死颜色。
- 字体用系统中文栈，数字和拉丁字母用一个等宽字体，让数据看起来像仪表盘。
  字号定五档，行高配套。
- 间距用一套 4 的倍数刻度。圆角、阴影、发光强度也各定一两个档。
- 加一点背景氛围。淡淡的网格线或者星点，不要抢内容。

动效要克制但要有。参数变化时数值要有一个短促的滚动或渐变，图表切换要有过渡，
约束通过和不通过要有颜色和图标的变化，不要用突然跳变。加载状态要有骨架或进度条。

## 第四件事 四个页面

### 4.1 前向预测

这是第一个页面，也是最重要的一个。

左侧是控制区。族别切换四位或五位。五位给 L、P、Q、T 四个控件，Q 用开关，
L 和 T 用滑块，P 也可以滑块。四位给 M、P、T。再加攻角和来流速度两个滑块。
每个控件旁边显示当前值和这个参数大致的影响方向。

中间是形状视图。用 canvas 或 SVG 画出翼型轮廓，横轴按弦长归一化，画上弦线
和弯度线，前缘加点标注。参数一动形状要连续变化，不要跳帧。

右侧上半是压力系数曲线。横轴是归一化弧长 `s`，范围 0 到 1，纵轴是 Cp，
注意纵轴要反过来，负值在上，这是气动的惯例。曲线底部填一层渐变。
再给一个切换，把这条闭环曲线折成上下表面两条弦向曲线叠画，让人看得懂形状和压力的关系。

右侧下半是流场云图。选 `p`、`u`、`v`、`nu_t` 四个量之一着色。
用契约里的 `grid.json` 加场数据渲染，掩膜外留黑，翼型位置描一条白边。
色标要标出单位和范围。可以加一条微弱的流线或者速度矢量层，让人看出流动方向。

底部是四个指标卡。8 度升力系数、带内损失、最大马赫数代理、分离代理。
每个卡显示数值和约束线，超出约束就变警告色并说明超出多少。

交互性能要求，拖动滑块到画面更新要在 100 毫秒以内。做法是拖动过程只更新
轻量的部分，重的场渲染用 `requestAnimationFrame` 节流。参数改变时 128 维几何
只算一次，缓存起来给模型和形状视图共用。

如果 `b_cp.onnx` 和 `b_field.onnx` 存在，就用 ONNX Runtime Web 在浏览器里跑真模型。
新建 `app/src/lib/models.ts` 负责加载会话和前向。输入是 `Float32Array(133)`，
先把五标量和几何向量用 `cp_basis` 里的统计量做 z-score 再拼起来。
模型输出 8 个或 128 个 POD 坐标，再乘基加均值还原成压力曲线或流场。
模型文件不在时退回到假数据，并在界面上标明当前是示例模式。
ONNX 跑不动时不要让页面崩，捕获错误后降级，把原因显示出来。

### 4.2 降维演示

顶部说明这个页面的意思，一千条真实数据用十几个数字就能概括。

左上是一个样本选择器。可以从一千条里搜名字或者随机抽，也可以按攻角和雷诺数筛。
选中后显示这条样本的真实压力曲线、几何形状和官方升力系数。

中间是主视图，给一个秩的滑块，从 1 到 8。显示重构曲线和真实曲线叠画，
再显示逐点误差，误差用另一种颜色或者下方的误差带表示出来。秩变化时
曲线要连续变化，能看出前几个模态抓到前缘吸力峰，后面的模态在修小细节。

右侧给模态面板。每个模态一个缩略曲线加一个贡献条，点击某个模态可以把这条
模态单独加到重构上看它修了什么。再给一个累计能量曲线，标出当前秩的位置。

底部给"上传你自己的数据"。支持拖拽或选择文件，格式按契约里
`samples.json` 那种结构，或者一个简单的 CSV，列名写成
`name,uInf,aoa,s,cp`。解析后按同一套基做投影，显示它的 POD 坐标和重构误差。
要在页面上写清楚支持的格式，并在格式不对时给出人能看懂的错误。

### 4.3 反向设计与对话

左边是对话区，右边是结果区。

对话区要有真实的聊天观感，气泡、时间、输入框在底部，回车发送。
用户说得含糊也要给回应，比如"我要一个八度附近升力高而且十度别掉的翼型"。

处理流程要可视化。用户发一句话之后，右侧依次出现三步状态，
第一步解析需求，第二步在候选里检索，第三步出形状和流场确认。
每一步都有一个小块显示状态和中间结果，从等待变成完成，
让人看见工具是一步一步被调用的。这是这个页面最重要的观感。

出结果之后右侧给四个东西。推荐的四个参数值，翼型形状，
压力曲线，以及三项约束的通过情况。再给一个备选列表，让人可以点着换。

设置面板必须做成现场输入。用户点右上角的设置按钮打开面板，
自己填接口地址、模型名称和 API key，填完立刻可用，不需要刷新。
面板里必须写一行提示，说明密钥只存在这个页面的内存里，关掉就没了。
代码里不许出现任何默认密钥、示例密钥或占位密钥，不许写
localStorage、sessionStorage、IndexedDB 和 Cookie。
仓库里也绝对不许出现真实密钥。没填密钥时自动用本地规则模式，
界面右上角用一个徽标显示当前是在线模式还是本地规则模式。
本地规则模式用关键词匹配加预计算结果，保证不联网也能完整演示。
